# 울음 기록과 알림 기준

## 발생 기록

- 파이 `cry_candidate_started/ended` → 브리지 `cry_started/ended` → DB `detection_events`에 저장한다. 개인화 학습용 `cry_episode_*`는 중복 집계하지 않는다.
- 실제 배포 모델의 시작/종료 신호는 서로 다른 식별자를 가진다. 같은 기기·아이 바인딩의 관측 시간으로 종료를 연결하며, 동일 요청 재전송은 중복 저장하지 않는다. 시작보다 먼저 도착한 종료도 원본 로그에서 대조한다.
- 조용해진 뒤 3초 이내 다시 감지되면 같은 발생 구간으로 병합한다. 3초보다 긴 간격 뒤 재감지는 새 기록이다. 이 값은 서버의 구간 병합 기준이며, 파이 개인화 모델의 `quiet_windows=3`과 별개다.
- 종료 없이 관측이 8초 넘게 끊기면 종료 미확인/관측 중단으로 표시한다. 신호 누락이나 기기 연결 해제를 울음 그침으로 판단하지 않는다.
- 종료 신호가 누락되어도 연속된 정상 오디오 상태에서 3초 이상 조용함이 확인되면 해당 조용한 구간의 시작 시각을 종료로 사용한다.
- 보호자 응답은 발생 시각·길이를 바꾸지 않는다. 하루 요약은 실제 발생 기록 수를 집계한다.

## 대응 알림

`cry_alert_groups`는 한 기기·아이의 미처리 알림을 한 건 유지한다. 알림 아래 여러 발생 기록을 연결하고 각 기록의 ID와 길이는 보존한다. `stopped` 응답은 알림을 처리 완료로 만든다. 같은 발생 신호의 재전송은 완료된 알림을 다시 만들지 않는다. 이후 새로운 발생은 새 알림에 연결된다. 단순 열람이나 `continues/reduced/unknown` 응답은 알림을 처리 완료로 만들지 않는다.

실시간 시작 신호(30초 이내)만 outbox 발송 대상이다. 과거 업로드와 마이그레이션은 새 푸시를 발송하지 않는다. outbox는 알림 그룹당 한 번만 적재한다. 실제 외부 푸시 발송 여부는 별도 전송 설정에 따른다.

## 분석 및 돌봄

현재 제공된 모델은 아기 울음·일반 울음 점수와 감지 여부를 제공한다. 배고픔·졸림 등 원인 분류 결과는 제공하지 않으므로 임의의 원인이나 확률을 만들지 않는다. 감지 구간 안에서 받은 오디오 점수를 해당 기록에 보존하고 이후 다른 구간의 점수로 덮어쓰지 않는다. 신뢰된 분석 콜백의 원인 후보·추천 행동이 있으면 함께 제공한다.

`care-history?kind=cries`는 `audioAnalysis`, `causes`, `recommendations`, `observationState`, `alertId`, `alertClosed`, `alertOccurrences`를 반환한다. 홈은 최신 오디오의 신선도를 확인한 뒤 결과를 표시하고, 상세는 해당 발생의 저장된 결과를 표시한다.

기본 돌봄 안내는 보호자 기록 수집이나 학습 건수에 의존하지 않는다. 상세 화면에서 결과 → 안내 → 실제 행동/반응 입력 순서로 진행하며 추천을 선택했다고 실제 행동을 자동 기록하지 않는다. 실제 행동·반응은 DB 돌봄 일지로 보존하고 파이 학습 명령으로 보내지 않는다. 모니터링 화면에는 학습용 기록 수집 UI를 노출하지 않는다.

## V10 이관

V9에서 합쳐진 발생을 원본 `sky_eye_events`로 재구성한다. `cry_projection_v9_backup`에 기존 연결을 보관하고 첫 기록의 ID와 보호자 응답을 유지한다. 대체된 옛 투영은 `cry_retired`로 보관하며 일반 목록·일일 집계에서는 제외한다. 원본 신호와 보호자 입력은 삭제하지 않는다.

검증: 별도 울음 두 건/알림 한 건, 3초 이내 재감지 병합, 시작·종료 ID 불일치, 순서가 바뀐 업로드, 재전송, 동시 시작, 연결 중단, 분석 점수 보존, 응답 버전 충돌, 기기 재연결 후 기록 보존, V9 데이터 이관.
