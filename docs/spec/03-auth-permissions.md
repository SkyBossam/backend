# 03. 인증·역할·정보 공유

## 인증
- 이메일/비밀번호 또는 외부 OAuth; API 인증은 짧은 수명 access token + 회전형 refresh token.
- 비밀번호 해시, 로그인 제한, 탈취 토큰 폐기, TLS 강제.
- 권한은 서버에서 매 요청마다 확인; JWT에 저장된 역할만으로 아이 접근 허가하지 않는다.
- 사용자 탈퇴/권한 회수 시 활성 세션 및 스트림 토큰 폐기.

## 역할 예시
| 역할 | 대표 권한 | 참고 |
|---|---|---|
| `owner` | 공간 관리, 관리자 임명, 아이별 접근 부여 | 개인 공간 기본 소유자 |
| `admin` | 기관 멤버 초대·자원 관리 | 아이별 열람은 별도 grant 필요 |
| `guardian` | 허용된 아이의 관찰·케어·루틴 수정 | 보호자 |
| `sitter` | 지정 아이 관찰/돌봄 기록, 시간 제한 | 개인 시터 |
| `staff` | 지정 아이 관찰/돌봄 기록 | 기관 소속 |
| `viewer` | 지정 아이의 승인된 최소 정보 열람 | 읽기 전용 |

## 아이별 capability (scope)
`child:read`, `routine:read`, `routine:write`, `cry:read`, `cry:feedback`, `monitor:live`, `detection:read`, `detection:ack`, `detection:resolve`, `notification:receive`, `child:manage`.
실시간 영상 권한은 `monitor:live`로 별도 통제. 위험 이벤트 읽기와 해결 처리도 각각 구분.

## 권한 판정 (모두 참이어야 허용)
1. 사용자 인증 및 계정 활성.
2. 활성 `membership`가 요청 `workspace_id`에 속함.
3. `workspace_children` 링크가 활성 상태.
4. `child_access_grants`가 현재 유효하고 필요한 capability 포함.
5. 공간 간 접근이라면 `data_share_grants`가 활성 및 해당 데이터 범위 포함.
6. 디바이스/스트림 자격 증명도 대상 공간·아이·짧은 만료를 만족.

## 시터 초대
- 보호자는 이메일 및 대상 아이, capabilities, 시작/만료일을 정해 초대 생성.
- 서버는 암호학적 난수 토큰 생성, DB에는 해시만 보관. 1회용, 짧은 만료(예: 48시간).
- 초대 수락 때 이메일 소유 확인, 사용자 계정과 membership 연결, 허가 범위 생성.
- 언제든 초대 철회 / 부여된 권한 회수. 이미 발급된 스트림 접근 토큰도 폐기.
- UI에서 초대를 아직 구현하지 않아도 백엔드 계약을 미리 정의할 수 있음.

## 기관과 부모 간 공유
- 기관 직원은 기관 membership만으로 개인 공간의 아이 정보를 볼 수 없다.
- 부모가 기관에 아이를 연결하는 흐름은 동의 근거, 공유 범위, 유효기간을 명시한 `data_share_grant`와 기관 링크에 의해 허용.
- 권한 철회 시 이후 API, 실시간 채널, 영상 접근 즉시 차단하고 캐시 무효화.
- 기관에서 생성한 이벤트를 부모에게 공유할 때는 이벤트 항목별 정책 검증. 기관 기록 전체 복제 금지.

## 접근 거부
- 다른 사람 아이 ID를 탐색할 수 없게 기본 404 사용; 인증 없는 경우 401, 동일 소유 영역에서 금지된 동작은 403.
- 리스트·검색·내보내기·통계 집계·WebSocket 구독에서도 동일 정책 적용.
