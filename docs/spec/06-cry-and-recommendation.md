# 06. 울음 AI 추천·행동 기록

## 사용자 흐름
1. `cry` 이벤트 감지 → 시작/종료 시점, 지속시간 저장.
2. 추천 서비스가 월령·최근 울음/반응·루틴을 참고해 원인 후보와 행동 우선순위 계산.
3. 부모/시터가 추천의 근거와 설명 확인.
4. 추천 행동별 `attempted` / `not_attempted` 선택, 선택적으로 메모.
5. 반응을 `stopped` / `reduced` / `continues` / `unknown` 중 선택.
6. 이벤트와 피드백 기록을 조회하며 이후 추천에서 활용.

## 원인 후보
`hunger | sleepiness | discomfort | illness_check | other`.
- `hunger`: 추정 원인 후보 **전용**. 수유 시각·수유량 저장 API/테이블을 새로 만들지 않는다.
- `illness_check`: 아픔 확정 진단이 아님. 증상 확인 및 의료진 도움 요청 지침.
- `score`는 내부 추정치. 보정/검증 전에는 확률 퍼센트를 UI에 제공하지 않음.

## 추천 방식
- MVP: 전문가 검토 안전 규칙 + 최근 사용자가 기록한 진정 효과(시간대/월령/맥락)로 정렬.
- 추후 ML: 행동 결과/상황 기반 랭킹 모델; 추천 버전 기록하고 평가 가능하도록 분리.
- 안전 관련 행동은 랭킹보다 상위 안전 규칙 우선.
- 근거 데이터가 부족하면 `insufficient_data` 및 일반 확인 가이드 표시.
- 추천 실패/시간 초과 시 사용자에게 명시하고 안전한 기본 점검 가이드 제공.

## 무결성
- 피드백은 이벤트와 동일한 아이/워크스페이스 범위를 가짐.
- 기록 생성자는 이벤트에 `cry:feedback` 권한 필요.
- 중복 요청 방지 키 사용, 멱등 응답 제공.
- 피드백 변경이 필요하면 수정 이력/버전 기록. 이전 결과 덮어쓰기 금지.
- recommendation은 추론 시점 스냅샷으로 저장해 나중에 모델이 바뀌어도 재현 가능.

## 권장 응답 구조
```json
{
  "eventId":"uuid", "status":"ready", "generatedAt":"2026-11-01T01:00:00Z",
  "causeCandidates":[{"key":"sleepiness","label":"졸림 가능성","rank":1,"disclaimer":"AI 추정"}],
  "actions":[{"id":"uuid","title":"편안한 환경 확인","priority":1,
    "explanation":"최근 진정 기록을 참고했어요","instructions":["조도를 낮춰 주세요"]}]
}
```
